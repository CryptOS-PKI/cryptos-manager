The Fleet Manager verifies every node's server certificate and refuses a node
that has neither a pinned server certificate nor a recorded CA chain. To list
how each node is verified:

  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "fleet-manager.name" . }} -- /manager -config /etc/cryptos/fleet/config.yaml -check-node-trust

fingerprint is in the log; check it in the browser before entering anything:

  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "fleet-manager.name" . }} | grep 'SELF-SIGNED'

{{- if and (not .Values.authBypass) (not .Values.operatorCA.configMap) (eq .Values.firstRun "auto") }}

No operatorCA.configMap: the operator CA is registered through first run.
While first run is open the manager logs a single-use bootstrap token, so keep
log access tight. To find it:

  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "fleet-manager.name" . }} | grep 'bootstrap token'
